# SLASH DATABASE SCHEMA

Canonical fields:
`slash_id, slash, canonical_name, aliases, category, subcategory, applicable_objects, semantic_type, quick_meaning, source_basis, ai_interpretation, prompt_foundation, visual_mechanics, what_changes, what_stays, best_for, when_to_use, visual_message, mood_perception, combine_with, conflicts_with, variations, pro_prompt, test_status, test_protocol_version, platform, model, tested_date, test_runs, success_runs, reviewer, review_status, test_notes, control_asset, test_assets, failure_assets, evidence_refs, last_updated`.

## Rules
1. One concept = one canonical entry where practical.
2. Aliases never inflate counts.
3. Cross-domain usage uses tags, not duplicates.
4. Macro ≠ semantic slash.
5. Lens terms are AI visual cues unless physical simulation is demonstrated.
6. Visual psychology is contextual, not universal.
7. Never fabricate test counts, dates, models or success rates.
8. New records default to UNTESTED + PENDING.
